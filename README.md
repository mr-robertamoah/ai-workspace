# AI Workspace CLI

## Overview

`ai-workspace` is a Python CLI that creates and maintains a structured engineering workspace so that AI agents and humans can collaborate on software projects without losing context between sessions.

It solves three problems: context loss between agent sessions, knowledge fragmentation across projects, and unreviewed AI-generated changes.

## Features

- **Workspace scaffolding** — generates `.ai/` context files and `docs/` structure
- **Existing project adoption** — detects technology stack and pre-populates context
- **Index system** — queryable YAML indexes so agents don't re-scan repositories
- **Summarization** — dependency summary, repo map, tech detection
- **Skills system** — reusable engineering patterns with governance (propose/accept)
- **Validation** — workspace health checks and security scanning
- **Docs system** — create ADRs, architecture docs, runbooks from templates
- **Handoffs** — timestamped handoff documents for agent session continuity

## Installation

### pip install

```bash
pip install ai-workspace
```

### Development install (editable)

```bash
python3 -m venv .venv
.venv/bin/pip install -e ".[dev]"
```

## Quick Start

### Initialize a new project

```bash
# Interactive mode
ai-workspace init

# From a YAML file
ai-workspace init --file workspace.yaml

# Dry run (preview only)
ai-workspace init --file workspace.yaml --dry-run
```

### Adopt an existing project

```bash
ai-workspace adopt
ai-workspace adopt --dry-run
ai-workspace adopt --force
```

### Rebuild indexes

```bash
ai-workspace index rebuild
```

### Summarize the project

```bash
ai-workspace summarize
```

### Generate a handoff

```bash
ai-workspace handoff generate
```

### Skills

```bash
ai-workspace skills list
ai-workspace skills search python
ai-workspace skills show python-package
ai-workspace skills propose
```

### Documentation

```bash
ai-workspace docs templates
ai-workspace docs create adr --title "Use PostgreSQL"
ai-workspace docs create architecture-overview
```

### Validation

```bash
ai-workspace validate
ai-workspace validate security
```

## Architecture

### Global Intelligence Layer (`~/.ai-workspace/`)

Persistent across all projects. Contains skills, standards, templates, and global indexes. Auto-initialized on first command invocation.

### Workspace Context Layer (`<project>/.ai/`)

Per-project context: summaries, repo maps, ADRs, active tasks, handoffs, and indexes. Generated by `init` or `adopt`.

### Indexing System

Four YAML indexes in `.ai/indexes/`: `docs-index.yaml`, `adr-index.yaml`, `task-index.yaml`, `repo-index.yaml`. Rebuilt with `index rebuild`.

### Skills System

Skills live in `~/.ai-workspace/skills/`. AI agents may only write to `<name>-proposed/` directories. Humans accept proposals with `skills accept <name>`.

## Agent Workflow

### Mandatory steps

1. Read `.ai/start-here.md`
2. Read `.ai/active-task/current-task.md`
3. Read the most recent file in `.ai/handoffs/`
4. Query `.ai/indexes/` before scanning any directory
5. Plan before coding
6. Run `ai-workspace validate` before finishing
7. Run `ai-workspace handoff generate` before ending session

### How to read context

```
.ai/start-here.md          ← always read first
.ai/project-summary.md     ← project overview
.ai/architecture-summary.md ← architecture decisions
.ai/active-task/           ← current work
.ai/handoffs/              ← previous session context
```

### How to query indexes

```bash
# Rebuild if stale
ai-workspace index rebuild

# Indexes are plain YAML — read directly
cat .ai/indexes/docs-index.yaml
cat .ai/indexes/adr-index.yaml
```

## Security Model

- Path traversal blocked on all file operations (`safe_path()`)
- YAML loaded with safe loader; `!!python/object` tags rejected
- Secret patterns detected in `.ai/` and `docs/` files
- File permissions checked for world-writable files
- `pip-audit` and `bandit` integration (graceful if not installed)
